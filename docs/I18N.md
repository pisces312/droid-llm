# I18N（中英双语）

> 状态：2026-09-29 落地。`values/` = 英文（兜底），`values-zh/` = 简体中文。

## 1. 结论速查

| 问题 | 答案 |
|------|------|
| 支持哪些语言 | 简体中文 / 英文。三态选择：**跟随系统 / 简体中文 / English** |
| 非中英文环境回落 | 英文（`values/` 是兜底）；`res/xml/locale_config.xml` 只声明 `en` / `zh` |
| 语言存在哪 | **`AppCompatDelegate`（app-locale）**，不由 app 自己存。Android 13+ 落到系统 `LocaleManager`；12 及以下由 AppCompat 存（manifest 里的 `autoStoreLocales`） |
| 谁负责应用 | `app/AppLanguageController`：`current()` / `set()`。**app 侧没有任何 `recreate()` 调用** —— recreate 由 AppCompat 自己做 |
| 设置项在哪 | 设置 → **语言**（`settings_language` 分组）；Android 13+ 系统「设置 → 应用 → droid-llm → 语言」是同一个值，两边都能改 |
| 生效的两个硬前提 | `MainActivity` **必须** `extends AppCompatActivity`；`Theme.DroidLlm` 的 parent 必须是 AppCompat 后代。少一条就静默失效或直接抛异常（见 §2） |

## 2. 机制

用平台 / AppCompat 的 per-app language。**不要自己包 Context**：那是 2026-09-29 的第一版方案
（`AppLocale.wrap` + 两处 `attachBaseContext` + `recreate()` + SharedPreferences 镜像），
2026-09-30 已整体删除，原因见下面的硬规则。

**硬前提一：`MainActivity : AppCompatActivity()`。** `AppCompatDelegate.setApplicationLocales()`
要靠 AppCompat 自己安装的 delegate 取一个 Context 去建系统 `LocaleManager`；`ComponentActivity`
从不安装 delegate → `sAppContext` 恒为 null → **整个调用静默空转**（现象：点了 English 毫无反应、
重启仍是中文，而设置值其实写进去了）。官方文档原文：

> Caution: If you're using Compose with `setApplicationLocales`, you must extend
> your activity from `AppCompatActivity`. Otherwise, setting the app locale won't work.

**硬前提二：`Theme.DroidLlm` 的 parent 必须是 AppCompat 主题**（现为
`Theme.AppCompat.DayNight.NoActionBar`），否则 `AppCompatActivity` 直接抛
`You need to use a Theme.AppCompat theme (or descendant) with this activity`。

四处配合：

1. **`res/xml/locale_config.xml` + manifest `android:localeConfig`**：声明 `en` / `zh`。
   Android 13+ 据此生成系统设置里的应用语言入口；官方要求**必须包含最终兜底语言**
   （本项目 `values/` 写的是英文）。AGP 8.1+ 也可用 `androidResources { generateLocaleConfig = true }`
   自动生成，但**与手写文件互斥**（同时存在会构建失败）。
2. **manifest `<service AppLocalesMetadataHolderService>` + `autoStoreLocales=true`**：只服务
   **API ≤ 32**。它让 AppCompat 自己持有存储、并在 Activity attach 时应用，冷启动首帧就是正确
   语言（否则先闪一帧设备语言）。本项目 `minSdk=31`，所以 31/32 依赖它 —— 这正是旧版
   `AppLanguageStore` 那份 SharedPreferences 镜像干的事，只是交给库做。官方承认会有一次主线程
   阻塞读（StrictMode 可能报 `diskRead`）。
3. **`app/AppLanguageController`**：`current()` = `AppCompatDelegate.getApplicationLocales()`
   （**空列表 = 跟随系统**），`set()` = `setApplicationLocales`。**刻意不加 Flow**：读取点的生命
   周期是「一次组合」——改语言必然 recreate、组合会重来；而 API ≤32 上这个读会碰磁盘，不能每次
   重组都读。所以 `SettingsScreen` 用 `remember { vm.currentLanguage() }`；
   `AppSettings` 不再承载语言（`language` 降级为只读的 `legacyLanguage`，见第 4 点）。
4. **迁移**：`MainActivity.onCreate` 调 `AppLanguageController.migrateLegacy(...)`，把旧 DataStore
   `app_language`（现名 `AppSettings.legacyLanguage`，**只读不写**）搬一次到新机制。
   位置有讲究：**必须在 Activity 里跑** —— `getApplicationLocales()` 只有在 delegate 存在之后才能
   区分「从没选过」和「存储还没挂上」，放在 `Application` 里跑会覆盖掉更新的选择。
   代价：升级后首次冷启动可能多一次 recreate（DataStore 是异步读）。
   **一版之后删掉 `legacyLanguage`、该 DataStore 键与这段迁移。**

### 硬规则一：`NavHost` 的 `startDestination` 必须是编译期常量

`androidx.navigation.compose.NavHost(navController, startDestination: String, …, builder)`
的实现体是：

```kotlin
NavHost(
    navController,
    remember(route, startDestination, builder) {
        navController.createGraph(startDestination, route, builder)
    },
    modifier,
)
```

即 **`startDestination` 是 `remember` 的 key**，而最终实现体里直接 `navController.graph = graph`。
传一个运行期会变的值（曾用 `object UiRoute { var current }` 配合 `LaunchedEffect(current)` 记住当前
tab），后果是：

- 值一变 → **NavGraph 重建并重新赋给 controller** → 回退栈被拆掉重建 → 过渡动画重启；
- 重启又让读 `currentBackStackEntryAsState()` 的那层重组失效 → **每帧循环、永不收敛**；
- 实测（模拟器，UI 英文，Chat→Models→Settings）：空闲 4s 内 **+26 帧**（健康态 0 帧）、
  每 4s **5~7 次 ~25MB GC**、PSS 239MB→287MB 持续上涨 → 最终 OOM 被杀，即「来回切几次就退出」。
  截图 / `uiautomator dump` 可见 Models 与 Settings 两块内容叠在同一屏，而底栏选中的是 Models。
- 次生伤害：back stack 里没有 `chat` 之后，`popUpTo("chat"){saveState}` **静默失效**（不抛异常、
  不报错），条目只增不减。

命中的是竞态：同一条序列实测 6 次命中 2 次。但结论不受影响 —— **只要 key 可变，这类不收敛就无法
排除**，修法只有把 key 变成常量。

### 硬规则二：`popUpTo` 用 `graph.findStartDestination().id`，不写死路由名

同一个坑的另一半：写死 `"chat"` 时，只要起点被改过一次，这个 `popUpTo` 就永远不再匹配，且不报错。
路由字符串集中在 `ui/DroidLlmRoot.kt` 的 `AppRoutes` 里，切 tab 统一走 `NavHostController.switchTab`。

### 不要自己写「跨 recreate 记住状态」的全局单例

`rememberNavController()` = `rememberSaveable(saver = NavControllerSaver)`，而
`NavControllerSaver` 就是 `save({ it.saveState() })` / `restore({ …restoreState(it) })`，
其 KDoc 原文是 **"across config change and process death"**。所以当前 tab 与整个回退栈本来就自动
恢复：**选完语言（recreate）不会把用户扔回首页**。旧版那个 `UiRoute` 不只多余，而且是**唯一**的
不稳定源。回归判据见 `app/src/androidTest/.../NavigationRecreateTest.kt`。

这条不变量不只覆盖切语言：改深色模式、字号、分屏同样会 recreate，所以**不能靠「避免 recreate」
来修**，只能靠起点恒定 + 状态交给库。

### 为什么不再需要自己存两份

旧方案必须在 `attachBaseContext` 里**同步**读语言，而 DataStore 与协程都来不及，所以要一份
SharedPreferences 镜像。现在存储由 AppCompat 持有，**镜像与双写一起删了**：`app_language`
这个 DataStore 键降级为只读的迁移源（§2 第 4 点），旧镜像文件 `droid_app_locale` 从此无人读、
无人写，残留内容无害。

### 已知残留 / 待核实

- **非 UI 路径的文案**：旧方案不 wrap Application Context，ViewModel 里 `getString` 造的
  Toast / 通知跟设备语言。改用 app-locale 后，Android 13+ 由系统 `LocaleManager` 在进程级应用，
  理论上会跟随应用语言；**API ≤32 是否如此未实测**，真机验收时顺手确认一次。
- **`ChatUiPersist` 的存在理由待复核**：它的 KDoc 写「recreate tears the ViewModel down」，
  而 `recreate()` 是配置变更路径，Activity 级 `ViewModelStore` 经 `NonConfigurationInstance`
  保留，这句话本身不成立；destination 级（`NavBackStackEntry`）的 store 以 entry 的 `id` 为键、
  而 `id` 默认是 `randomUuid()`，是否随保存状态一起恢复**未实测**。它用的是普通
  `MutableStateFlow` / `@Volatile var`，**没有**出现在任何 `remember` key 里，与本次故障无关，
  故本次未改动。动它之前先实测「切语言后 per-destination ViewModel 是否被重建」。

## 3. 资源分布

| 模块 | 资源文件 | 条数 | 说明 |
|------|---------|------|------|
| `app` | `values[-zh]/strings.xml` | 359 | UI + ViewModel/service 状态文案 |
| `core:benchmark` | `values[-zh]/strings.xml` | 9 | 评测用例/提示词**标签** + 运行期状态 |
| `core:engine-api` | `values[-zh]/strings.xml` | 8 | `applicability_*`（参数适用性提示） |
| `engine:genie` | `values[-zh]/strings.xml` | 16 | Genie 加载/生成失败原因 |

**库模块看不到 app 的 `R`**，所以每个有文案的库模块各带一份 `res/`。
`R` 生成在各自 namespace 包下，同包内引用**不需要 import**。

`app_name` 故意不在 `strings.xml` 里：由 buildType 的 `resValue` 提供，
debug / release 才能同机并存。

## 4. 占位符约定

Kotlin 字符串模板 → Android 位置占位符，避免各语言语序不同：

```kotlin
// 反例："当前 SoC=$soc，支持 ${list.joinToString()}"
context.getString(R.string.genie_unsupported_soc, soc, list.joinToString())
```
```xml
<string name="genie_unsupported_soc">Genie supports Snapdragon HTP only; current SoC=%1$s; supported: %2$s</string>
```

生成 XML 时若源串已含 `%`，**不要再做一次模板转换**（曾出现 `%1%1$s`）。

## 6. 加新文案的规矩

1. **不要直接在 Kotlin 里写中文/英文字符串**，先加 `values/strings.xml`（英文）+ `values-zh/strings.xml`（中文）。
2. Compose 用 `stringResource(R.string.x)`；ViewModel / service 用注入的 `@ApplicationContext` + `getString(...)`。
3. Chip / 下拉项等**需要 `stringResource` 的 label**，签名必须是 `@Composable (T) -> String`
   （普通 `(T) -> String` 里调不了 `stringResource`）。
4. 判定「是不是报错文案」**不要**用 `message.startsWith("校验失败")` 这类字符串匹配 ——
   语言一换就失效。改成 ViewModel 显式下发 `messageIsError` 标志。
