# I18N（中英双语）

> 状态：2026-09-29 落地。`values/` = 英文（兜底），`values-zh/` = 简体中文。

## 1. 结论速查

| 问题 | 答案 |
|------|------|
| 支持哪些语言 | 简体中文 / 英文。三态选择：**跟随系统 / 简体中文 / English** |
| 非中英文环境回落 | 英文（`values/` 是兜底） |
| 语言存在哪 | DataStore `app_language`（`AppSettings.language`），**唯一真源** |
| 怎么生效 | `AppCompatDelegate.setApplicationLocales()`，进程启动时 + 运行中切换各推一次 |
| 设置项在哪 | 设置 → **语言**（`settings_language` 分组） |

## 2. 机制

三个组件，改动前必须都过一遍：

1. **`AppLocale.apply(language)`**（`app/.../AppLocale.kt`）
   `SYSTEM` → `LocaleListCompat.getEmptyLocaleList()`；否则 `forLanguageTags(tag)`。
   **不能用 `Locale.getDefault()`** —— 那会把当前设备语言固化下来，之后改系统语言 App 不再跟随。
2. **`DroidLlmApp`** 进程启动时读一次 DataStore 并 `applyLanguage()`（在 `Dispatchers.Main` 上）。
3. **`MainActivity`** `LaunchedEffect(language)` 监听运行中变更并 apply。

Manifest 必须声明（AppCompat 要求，缺了 `setApplicationLocales` 抛异常）：

```xml
<service android:name="androidx.appcompat.app.AppLocalesMetadataHolderService"
         android:enabled="false" android:exported="false">
    <meta-data android:name="autoStoreLocales" android:value="false" />
</service>
```

`autoStoreLocales=false`：**AppCompat 自己的自动持久化必须关掉**，否则它会在
`SharedPreferences` 里另存一份，与 DataStore 的三态选择打架（AppCompat 只能表达「具体 locale 或空」，
表达不出「用户显式选了中文但系统当前是英文」之外的状态持久化，两处真源必然漂移）。

## 3. 资源分布

| 模块 | 资源文件 | 条数 | 说明 |
|------|---------|------|------|
| `app` | `values[-zh]/strings.xml` | 359 | UI + ViewModel/service 状态文案 |
| `core:benchmark` | `values[-zh]/strings.xml` | 9 | 评测用例/提示词**标签** + 运行期状态 |
| `core:engine-api` | `values[-zh]/strings.xml` | 8 | `applicability_*`（参数适用性提示） |
| `engine:genie` | `values[-zh]/strings.xml` | 16 | Genie 加载/生成失败原因 |

**库模块看不到 app 的 `R`**，所以每个有文案的库模块各带一份 `res/`。
`R` 生成在各自 namespace 包下，同包内引用**不需要 import**。

`app_name` 故意不在 `strings.xml` 里：由 buildType 的 `resValue` 提供，
debug / release 才能同机并存。

## 4. 占位符约定

Kotlin 字符串模板 → Android 位置占位符，避免各语言语序不同：

```kotlin
// 反例："当前 SoC=$soc，支持 ${list.joinToString()}"
context.getString(R.string.genie_unsupported_soc, soc, list.joinToString())
```
```xml
<string name="genie_unsupported_soc">Genie supports Snapdragon HTP only; current SoC=%1$s; supported: %2$s</string>
```

生成 XML 时若源串已含 `%`，**不要再做一次模板转换**（曾出现 `%1%1$s`）。

## 5. 故意没有抽取（白名单）

改这些文件时不必纠结，它们**本就该保持原样**：

| 位置 | 为什么 |
|------|--------|
| `core/benchmark/.../BenchmarkPrompts.kt`、`BenchmarkModels.kt` 的 `decodePromptText` | **提示词正文**。翻译后各语言跑出的数字不可比，评测失去意义。只翻译 chip 上的**标签** |
| `JsonExporter.kt` 的 `disclaimer` | 导出 JSON 是跨设备交换的数据，不带 Context，应语言中立 |
| `core/common/.../diag/CrashReporter.kt`、`EngineLogcatCapture.kt` | 诊断日志/崩溃附件内部文案，给开发者看 |
| `ModelRootMigrator.kt` 的 2 条错误 | 纯 JVM 单测（`TemporaryFolder`）直接调用 `object` 方法，加 `Context` 参数要改 7 处测试，收益极低 |
| `SettingsBundle.summary()` | **死代码**（全仓库无调用点），保留原样即可 |

## 6. 加新文案的规矩

1. **不要直接在 Kotlin 里写中文/英文字符串**，先加 `values/strings.xml`（英文）+ `values-zh/strings.xml`（中文）。
2. Compose 用 `stringResource(R.string.x)`；ViewModel / service 用注入的 `@ApplicationContext` + `getString(...)`。
3. Chip / 下拉项等**需要 `stringResource` 的 label**，签名必须是 `@Composable (T) -> String`
   （普通 `(T) -> String` 里调不了 `stringResource`）。
4. 判定「是不是报错文案」**不要**用 `message.startsWith("校验失败")` 这类字符串匹配 ——
   语言一换就失效。改成 ViewModel 显式下发 `messageIsError` 标志。
